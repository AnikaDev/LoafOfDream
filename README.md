# LoafOfDream

**Мобильное приложение для автоматизации учёта производства, продаж и остатков готовой продукции пекарни/кондитерской**

---

## Описание

«LoafOfDream» («Каравай мечты») — клиент-серверное мобильное приложение для малого пищевого производства.  
Позволяет вести учёт выпуска продукции, оформлять продажи, контролировать складские остатки и автоматически выявлять просроченные товары.

**Целевая аудитория:** владельцы и сотрудники пекарен, кондитерских, небольших производств.

**Ключевые особенности:**
- Разграничение ролей (владелец / продавец)
- Учёт производства с привязкой к дате
- Контроль остатков при продажах (нельзя продать больше, чем произведено)
- Автоматическое определение просроченных позиций
- Отчёты о выручке за день, неделю, месяц
- Календарная статистика продаж
- Тёмная и светлая тема

## Бизнес-требования

### Цели создания

- Автоматизация учёта — замена бумажных носителей и Excel-таблиц.
- Оперативный контроль — актуальные остатки и продажи в реальном времени.
- Снижение потерь — автоматическое выявление просрочки.
- Повышение эффективности — аналитика для принятия решений.
- Мобильность — доступ с любого Android-устройства.
- Разграничение доступа — чёткое разделение функций между владельцем и продавцом.
- Экономическая целесообразность — бесплатное решение без абонентской платы.

### Бизнес-ценность

- Снижение ручного труда (исключение двойного ввода данных)
- Ускорение операций (оформление продажи/производства < 1 минуты)
- Контроль потерь (снижение списаний до 30%)
- Прозрачность (все операции видны владельцу)
- Аналитика (выявление трендов и корректировка ассортимента)

## Пользовательские требования

### Требования продавца

1. Авторизоваться по логину и паролю.
2. Просматривать каталог с ценами и остатками.
3. Искать продукты по названию (с историей поиска).
4. Оформлять продажи (выбор товара и количества).
5. Видеть только доступные к продаже товары (произведённые и не проданные).
6. Удалять ошибочно оформленные продажи.
7. Просматривать остатки (разделение на «В наличии» и «Просроченные»).
8. Смотреть выручку за день, неделю, месяц.
9. Просматривать календарь продаж с динамикой по дням.
10. Переключать светлую и тёмную тему.

### Требования владельца (дополнительно к продавцу)

1. Выполнять все действия продавца (пункты 1–10 выше).
2. Добавлять новые продукты (название, категория, цена, срок реализации).
3. Редактировать информацию о продукте.
4. Удалять продукты (с каскадным удалением связанных записей).
5. Фиксировать выпуск продукции с привязкой к дате.
6. Удалять записи о производстве.
7. Просматривать журнал производства за выбранную дату.
8. Устанавливать глобальную рабочую дату через календарь.
9. Видеть автоматически определяемые просроченные позиции.
10. Регистрировать новых пользователей с назначением роли.

## Функциональные требования

### Модуль аутентификации

- Регистрация пользователя (имя, email, пароль, роль).
- Авторизация по имени/паролю с выдачей JWT-токена.
- Сохранение токена локально и автоматическая подстановка в запросы.
- Выход из аккаунта с очисткой токена.

### Модуль управления продуктами

- Отображение каталога с поиском по названию.
- Фильтрация по дате (показывать остаток на дату).
- CRUD-операции для продуктов (только владелец).
- Каскадное удаление (продукт → производство → продажи).
- Атрибуты продукта: название, категория, цена, количество, срок реализации (часы), фото (опционально).
- Сохранение истории поиска (до 10 записей).

### Модуль учёта производства

- Фиксация выпуска продукции (дата, продукт, количество).
- Увеличение складского остатка при добавлении.
- Удаление записи производства с уменьшением остатка.
- Отображение журнала производства за дату.

### Модуль продаж

- Оформление продажи (продукт, количество).
- Проверка наличия товара на дату (произведено – продано).
- Уменьшение остатка при продаже.
- Фиксация цены на момент продажи.
- Список продаж за дату с итоговой суммой.
- Удаление записи продажи.

### Модуль аналитики

- Отображение текущих остатков всех продуктов.
- Автоматическое определение просрочки (lastProducedAt + shelfLifeHours < now).
- Отчёт о выручке за день, неделю, месяц.
- Календарная статистика за день, месяц, год.

### Навигация и интерфейс

- Поддержка тёмной и светлой темы (сохранение выбора).
- История поиска (до 10 записей).
- Глобальная дата, применяемая ко всем экранам.

## Нефункциональные требования

### Производительность

- Время отклика ≤ 3 секунды при стабильном интернете.
- Поддержка Android 8.0 (API 26) и выше.

### Безопасность

- Хранение паролей в хэшированном виде (BCrypt).
- Все защищённые эндпоинты требуют валидный JWT-токен.
- Проверка прав доступа на стороне сервера.
- Автоматическое добавление токена в заголовок `Authorization: Bearer <token>`.

### Надёжность

- Информативные сообщения об ошибках сети.
- Кнопка повторной загрузки на экране списка продуктов.
- Атомарность транзакций на сервере.

### Удобство использования

- Полная локализация на русском языке.
- Тёмная и светлая тема.
- Сохранение истории поиска между сессиями.

### Технические требования

- Клиент: Kotlin + Jetpack Compose.
- Сервер: Kotlin + Ktor.
- База данных: PostgreSQL + Exposed ORM.
- Взаимодействие: REST API + Retrofit2.
- Аутентификация: JWT.

## Use Case (варианты использования)

### Акторы

- **Продавец** – обслуживает покупателей, имеет ограниченный доступ.
- **Владелец** – полный доступ ко всем функциям.

### Диаграмма вариантов использования (прикреплена ниже)


### Описание ключевых Use Case

#### UC-01: Авторизация
- **Актор:** Продавец, Владелец
- **Предусловие:** Пользователь зарегистрирован
- **Основной поток:** Ввод имени/пароля → проверка → выдача JWT → переход на главный экран
- **Альтернативный поток:** Неверные данные → сообщение об ошибке
- **Постусловие:** Пользователь авторизован, токен сохранён

#### UC-02: Оформление продажи
- **Актор:** Продавец, Владелец
- **Предусловие:** Авторизован, есть произведённые товары за дату
- **Основной поток:** Выбор товара → ввод количества → проверка остатка → сохранение продажи, уменьшение остатка
- **Включаемый UC:** Просмотр остатков (для проверки доступности)
- **Альтернативный поток:** Недостаточно товара → ошибка
- **Постусловие:** Продажа оформлена, остаток обновлён

#### UC-03: Добавление производства
- **Актор:** Владелец
- **Предусловие:** Авторизован как владелец, есть продукт в каталоге
- **Основной поток:** Выбор продукта → ввод количества → сохранение записи, увеличение остатка
- **Включаемый UC:** Просмотр каталога продуктов
- **Постусловие:** Запись производства сохранена, остаток увеличен

## User Story (пользовательские истории)

### Для продавца

- **US-01:** Как продавец, я хочу авторизоваться по логину и паролю, чтобы получить доступ к системе учёта.
- **US-02:** Как продавец, я хочу просматривать каталог продукции с ценами и остатками, чтобы быстро отвечать на вопросы покупателей.
- **US-03:** Как продавец, я хочу искать товары по названию с автодополнением из истории, чтобы экономить время при частых запросах.
- **US-04:** Как продавец, я хочу оформлять продажи в один клик, чтобы быстро обслуживать очередь покупателей.
- **US-05:** Как продавец, я хочу видеть только доступные к продаже товары, чтобы не пытаться продать то, чего нет в наличии.
- **US-06:** Как продавец, я хочу удалять ошибочные продажи, чтобы исправлять ошибки без обращения к владельцу.
- **US-07:** Как продавец, я хочу видеть остатки с разделением на просроченные и годные, чтобы не продавать просроченный товар.
- **US-08:** Как продавец, я хочу смотреть выручку за день, чтобы понимать свою эффективность.

### Для владельца

- **US-09:** Как владелец, я хочу добавлять новые продукты в каталог, чтобы расширять ассортимент пекарни.
- **US-10:** Как владелец, я хочу редактировать цену и срок реализации продукта, чтобы оперативно реагировать на изменения.
- **US-11:** Как владелец, я хочу удалять продукты (с подтверждением), чтобы убирать неактуальные позиции из каталога.
- **US-12:** Как владелец, я хочу фиксировать выпуск продукции, чтобы вести точный учёт производства.
- **US-13:** Как владелец, я хочу видеть журнал производства за любой день, чтобы контролировать объёмы выпуска.
- **US-14:** Как владелец, я хочу автоматически получать информацию о просроченных товарах, чтобы своевременно их списывать.
- **US-15:** Как владелец, я хочу видеть выручку за неделю и месяц, чтобы анализировать динамику продаж.
- **US-16:** Как владелец, я хочу просматривать календарь с продажами по дням, чтобы выявлять пиковые и провальные даты.
- **US-17:** Как владелец, я хочу устанавливать глобальную дату для просмотра данных за любой день, чтобы анализировать историю.
- **US-18:** Как владелец, я хочу регистрировать продавцов с ограниченными правами, чтобы давать доступ сотрудникам без риска изменения каталога.
- **US-19:** Как владелец, я хочу переключать тёмную тему, чтобы комфортно работать в вечернее время.
